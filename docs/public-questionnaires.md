## Что взять / чего не копировать

Взять:
- Структуру и приёмы разметки как тестовые случаи для парсера: см. таблицу «трудные случаи».
- Правила подсчёта вопросов из `truth.json` (ID-шаблон `XXX-NN(.N)`, исключение GNRL/DATE, исключение дублирующих листов) как основу для проверочного набора «выделено ≥95%» (ТЗ Andersen, п. 9).
- Важный технический вывод для кода: openpyxl при загрузке отбрасывает data validation в расширении x14 (предупреждение «Data Validation extension is not supported and will be removed», HECVAT Lite и 4.16); при сохранении через openpyxl эти выпадающие списки пропадут. Допустимые значения надо читать из сырого XML. (Это замечание про текущий код проекта; код я не менял и не проверял.)
- В HECVAT 4.16 текст вопроса — формула; без кэшированного значения или чтения скрытого листа `Questions` вопрос не виден.

Не копировать:
- Файлы CAIQ и HECVAT в публичный репозиторий: у CAIQ запрет на распространение прямо в файле, у HECVAT авторское право EDUCAUSE и лицензия не подтверждена. В демо-репозиторий их класть нельзя; можно держать `data/public/` вне git и дать скрипт загрузки по ссылкам из этого документа (предположение: так допустимо, юридически не проверялось). Права на использование для тестирования у CSA указаны как личное некоммерческое.
- Файл IU: заполненные ответы и контакты человека.
- `truth.json` содержит до 160 символов текста вопросов (цитаты); для распространения проверить так же, как сами файлы.
- `.gitignore` на `data/public/` не настроен (я его не менял): перед коммитом добавить исключение или решить, что оставлять.
