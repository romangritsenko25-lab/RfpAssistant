# Code review standard

## Mandatory review

No change reaches the main branch without a merge request that has been reviewed. Direct pushes to the main branch are blocked in GitLab. The author cannot approve their own merge request.

## Number of approvers

One approval is required for regular changes. Two approvals are required for changes to authentication, authorization, cryptography, payment logic and infrastructure code. At least one approver must be listed in the CODEOWNERS file for the changed path.

## Size and timing

Merge requests should not exceed 400 changed lines; larger changes are split. A reviewer responds within 1 business day.

## Automated checks

Before human review, the pipeline must pass linters, unit tests, static analysis (SAST) and the dependency check (SCA). A merge request with a critical or high finding cannot be merged. Coverage of new code must be at least 80%.

## What reviewers check

Reviewers check correctness, readability, test quality, error handling, logging without personal data, and conformity with the architecture decisions of the project.
